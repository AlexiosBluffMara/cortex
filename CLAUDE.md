# Cortex — working notes for Claude Code

## What this is

Cortex by Alexios Bluff Mara LLC (Red Team Kitchen). A multimodal brain-response analysis system: video/audio/text in → Gemma 4 vision-gates and narrates, TRIBE v2 predicts BOLD activation → Three.js renders the cortex in 3D. Targets the **Gemma 4 Good Hackathon** (deadline May 18, 2026; today is Apr 25).

The full architecture lives in [SPEC.md](SPEC.md). The day-by-day plan is in [SPRINT_PLAN.md](SPRINT_PLAN.md). Read both before suggesting structural changes.

## Hard invariants (do not violate)

1. **Gemma 4 only.** No Gemma 3 anywhere. Model tags: `gemma4:e2b`, `gemma4:e4b`, `gemma4:26b`, `gemma4:31b`. No closed-source LLMs in the hot path.
2. **Never override `duration_trs`.** TRIBE v2 is hard-locked at 100 TRs (50s @ 2Hz). The pipeline enforces this; do not add a config knob to "extend" it — that silently corrupts inference.
3. **TRIBE v2 weights are CC-BY-NC 4.0.** This repo is Apache 2.0 *for the code* — the weights are not redistributable here, and the project is not commercial.
4. **GPU swap is sequential, never concurrent.** TRIBE (~22 GB) + Gemma E4B (~10 GB) ≠ 32 GB. The `GPUScheduler` is the only path to GPU access; don't bypass it.
5. **All errors return structured `CortexError` objects** (see `cortex/errors.py`). Do not raise raw `RuntimeError` from public APIs — wrap and classify.
6. **"Gemma is a trademark of Google LLC."** Must appear in the README, model card, and demo video. The fine-tuned model is `RedTeamKitchen/cortex-gemma-4-e4b` (Gemma referenced in the path, not the product name).

## Code conventions

Inherit from `~/.claude/CLAUDE.md`, plus:

- **No `Co-Authored-By: Claude`** in commits. Match existing commit style (`git log --oneline | head` first).
- **No `# Generated by Claude`** comments anywhere.
- **No unprovoked docstrings.** Comment only when the *why* is non-obvious — hidden constraint, subtle invariant, hardware quirk.
- **Validate at system boundaries only.** `media_gate.py` validates uploads; internal calls trust their callers.
- **Async-first** for anything that touches I/O or the GPU scheduler. Sync helpers exist for tests and CLI.
- **No Discord/WhatsApp/Telegram bot logic in `cortex/`.** Those go in `hermes/` (agent integration) or a future `bot/` package.

## Testing

- `pytest -m unit` — fast unit tests with mocked Ollama, mocked nvidia-smi, no GPU. Must pass before any commit.
- `pytest -m integration` — touches a real local Ollama. Skipped in CI; run locally before claiming a feature works.
- `pytest -m "tribe and gpu"` — full inference, requires the 5090 + TRIBE weights.
- New code requires tests. If you ship a bare module, the next session is going to write the tests anyway — write them with the code.
